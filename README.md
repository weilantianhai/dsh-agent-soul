# dsh-agent-soul

> 给 DSH 的 agent 一套**可查的记忆**，和一个**立得住的人格**。

DSH 的上下文会被压缩，压缩完就忘了，没有长期记忆。

DSH没有跨会话记忆。

DSH记不住你。

这个插件给你的agent赋予了人格，让Ta在你电脑上有一个家。

Ta有自己的长期记忆，能跨会话记忆，可以设定自己的人格，更能记住你。

人格不是配置项，是文件。日记不是数据，是它明天还认不认得自己的凭据。

---

## 它每天在做什么

| 什么时候 | 做什么 |
|---|---|
| 一直在 | 你说的话、它回的话，实时写进日志 |
| 每轮开口前 | 系统提示里多一段：它是谁、最近写过什么、去哪翻 |
| 上下文到 80% | 叫它写一份**交接总结**（我正在干啥、干到哪了），只在它不忙的时候叫 |
| 晚上 23:30 | 挑今天活动过、有人格的会话，产一份对话稿，叫醒它当场写日记 |
| 随时 | 它想不起细节，用五个工具去翻 |

## 兼容性

**为 DSH `0.2.1-rc.2` 写的。其他版本未经测试。**

这个插件贴着宿主的内部接口写（`system-prompt/assemble`、`tools/pre-execute`、
`sessionController.prompt`、`sessionProjections.stateOf` 等），
这些不是稳定的公开 API。宿主一改，它可能就不工作了 —— 而且**是静默地不工作**，
不会报错，只是某个功能突然没了。

已知依赖的宿主接口（判断兼容性时可以对照）：

| 依赖 | 用在哪 | 找不到会怎样 |
|---|---|---|
| `system-prompt/assemble` | 每轮注入人格和日记 | 系统提示里没有记忆 |
| `tools/pre-execute` | 跨人格隐私边界 | 边界失效（不报错） |
| `sessionController.list()` | 会话登记 | 会话表空 |
| `sessionController.prompt()` | 叫醒写日记、写总结 | 叫不醒 |
| `sessionProjections.stateOf()` | 读上下文压力 | 摘要触发不了 |
| `ctx.sessions.flush()` | 确认消息真的落盘 | 消息可能只进了内存 |

装之前先在设置页跑一次**体检** —— 七块哪块 `missing`，就是哪个接口对不上。

## 装

```bash
git clone <这个仓库> dsh-agent-soul

# 方式一：CLI
dsh plugin --profile desktop add "link:<克隆下来的绝对路径>"

# 方式二：让 DSH 自己的插件管理器装（在会话里对 agent 说）
#   plugin_manager install_bundle target=<克隆下来的绝对路径>
```

装完**重启 DSH**。日志里看到这一行就算起来了：

```
[dsh-agent-soul] 已启动 Sessions=on Log=on Inject=on Tools=on Daily=on ...
```

`desktop` profile 被 Electron 独占时 `dsh plugin` 会拒，用方式二。

## 数据放在哪

**插件本体和数据是分开的。** 装插件不会在你的代码目录里建任何东西。

默认数据根目录按这个顺序找：

1. 环境变量 `DSH_MEMORY_ROOT`
2. `D:/ProgramData/dsh/memory`（这台机器上正在用的）
3. `$DSH_HOME/memory` → 再不行 `~/.dsh/memory`

目录长这样：

```
memory/                                   ← 数据根，可以放任何地方
│
├── agents/                               ← 每个 agent 一个家
│   └── <人格>/
│       ├── 人格.md                       我是谁、怎么说话、红线在哪
│       ├── MEMORY.md                     记忆总览
│       ├── INDEX.md                      目录（它自己的记忆地图）
│       ├── 经验.md                       摔出来的教训
│       ├── people/                       认识的人
│       │   └── <名字>.md
│       ├── diary/                        过的日子
│       │   └── <会话>/<日期>.md
│       └── summary/                      交接总结（上下文快满时写的）
│           └── <会话>/<日期>-<时分>.md
│
├── sessions/<会话>/logs/<日期>.jsonl      ← 原料：只增不改
├── shared/board.md                       ← agent 之间唯一能互相看见的地方
├── private/agents.json                   ← 会话 → 人格 的归属表
└── system/                               ← 机器维护，别手改
    ├── sessions.json                     会话登记表
    ├── plugin-status.json                诊断快照
    └── log.config.json                   日志模块的配置
```

**整个 `memory/` 都可以用 git 管、用编辑器看、手工改。** 全是普通文本。

## 五个工具

| 工具 | 干什么 | 什么时候用 |
|---|---|---|
| `memory_index` | 读自己的 `INDEX.md` | **刚醒来、脑子空白**，先看地图。很便宜 |
| `memory_find` | 按关键词找，给 id + 一句摘要 | 主人说「上次」「之前」，你不确定藏在哪 |
| `memory_open` | 打开一本读全文 | 摘要不够，要引用原话 |
| `memory_diary` | 按日期看日记的「总结」段 | 「最近怎么样」「这几天在干嘛」 |
| `memory_recall` | 查某天的原始对话 | **只在写日记前拿稿子，或真要回查时** |

每个都可以在设置页单独关。关掉哪个，它在那个问题上就够不着。

## 人格

**一个会话归一个人格。** 归了谁，日记就写进谁的目录，注入就用谁的口气。

三种状态：

| 设置 | 意思 |
|---|---|
| 选了某人 | 用它 |
| 「不要人格」 | 这一趟当临时会话，不记日记、不注入 |
| 「跟随默认」 | 用设置里的默认人格 |

### 建人格

设置页有个「一键建立」：起个名字，它读完那段对话，把人格、记忆、认识的人**自己写出来**。

之后可以手工调 —— `agents/<人格>/` 下都是普通 markdown。

## 设置页

侧边栏「记忆与人格」点开是整页，也能从设置进入。分这几块：

**记忆** —— 三盏状态灯（日志 / 注入 / 写日记），绿=正常 红=报错

**快速创建人格** —— 起个名字就完事

**默认** ——
- 默认日志记录 / 默认日记记录
- 默认写日记时间
- 新会话默认人格
- 上下文到多少写交接总结

**会话管理** —— 按工作区分组，可折叠。点开单个会话能看到它自己的：日志开关、日记开关、人格

**Agent 人格管理** —— 字数预算、人格列表、新建人格、打开共享话板。
每个人格会显示**名下有几个会话**（总数 + 其中真聊过的），点开能看到具体是哪些，点一个就跳到它的设置。
展开后还能「编辑人格」和「在资源管理器中打开」。

**Tools** —— 总闸 + 四个开关

**出问题了** —— 体检按钮，把错误列出来，可复制

## 隐私边界

`agents/` 下每个目录属于一个人格。**A 不该碰 `agents/<B>/`。**

这条有代码层的硬边界：

| 工具 | 拦不拦 |
|---|---|
| 读文件 / 写文件 / 改文件 / 切目录 | **拦** —— 碰别人的目录会**弹出来让你确认** |
| `ops_bash` | **不拦** —— 靠提示词约束 |

**这层不受 DSH 沙箱模式影响。** 哪怕会话是完全权限，碰别人的目录仍然要确认。

`ops_bash` 为什么不管：命令是字符串，路径能拼、能 `cd`、能 base64：

```bash
cd D:/ProgramData/dsh/memory/agents && cat 小鱼/人格.md   # 没有一个字是完整路径
```

在字符串上做边界，防不住还会给人虚假的安全感。

## 提示词都能改

`prompts/` 下全是 markdown，**改完存盘下一轮生效**，不用重启、不用重新打包。

| 文件 | 是什么 |
|---|---|
| `inject/00-manual.md` | 插件使用说明（每轮注入） |
| `inject/99-designer-note.md` | 小鱼留的话（每轮注入） |
| `inject/20-board.md` | 话板有新留言时的提醒 |
| `daily/00-wake.md` | 晚上叫醒写日记的词 |
| `persona/10-bootstrap-command.md` | 一键建人格时投给会话的指令 |
| `INDEX.md` | 提示词总表（哪个能改、什么时候出现） |

`_doc-` 开头的是给人看的说明，不会发给模型。

**想只改自己那一份**：在 `<数据根>/prompts/` 放同名文件，优先生效。

## 想改它

这个仓库是分开的：**用户文档**（你正在读的这份）讲怎么用，
`docs/` 下面三份讲怎么改。

| 文件 | 讲什么 |
|---|---|
| [`docs/MODEL.md`](docs/MODEL.md) | **先读这个。** 会话是什么、什么叫"还在"、消息什么时候算送到 —— 每个概念的依据都给出来，还标了哪些是我们自己拍的、可以商量 |
| [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md) | 代码怎么分层、依赖往哪边走、数据怎么流 |
| [`docs/CONTRIBUTING.md`](docs/CONTRIBUTING.md) | 怎么加接口 / 工具 / 模块，以及这个仓库踩过哪些坑 |

```bash
npm test                       # 全套（含真机验证）
node tools/check-deps.mjs      # 双向依赖 + 死代码
```

改后端要重启 DSH；只改 `client.js` 刷新页面就行。

**提示词不用改代码。** `prompts/` 下的 md 存盘即生效，
`_doc-` 前缀是给人看的说明，其余才是发给模型的。

三份的读法：

```
MODEL.md        这个概念是谁定的？宿主给的还是我们拍的？
    ↓          （标了 ❓ 的是我们拍的，可以商量）
ARCHITECTURE.md 它在代码哪一层？为什么放那层？
    ↓
CONTRIBUTING.md 改它要注意什么？以前在这上面栽过什么跟头？
```

**三份对不上时，以 `MODEL.md` 为准** —— 然后去改代码或改文档。
概念错了，代码写得再漂亮也是错的。

（改动历史在 `git log` 里。工作记录不进仓库：仓库是给接手的人看的。）

## 卸载

从 profile 的 `cordis.patch.yml` 里去掉 `dsh-agent-soul` 那一行，删包，重启。

卸掉之后：它照常说话，但不再记日志、不再注入。**人格还撑着，日子不长了。**

已经写下来的 `memory/` 一个字不掉。
