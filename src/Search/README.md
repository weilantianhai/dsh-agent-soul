# Search —— agent 用来翻记忆的那五个工具

> → 这份讲**怎么用**：模块干什么、怎么跑、怎么验、硬边界在哪。查函数签名去 [`API-REFERENCE.md`](API-REFERENCE.md)。

> DSH 记忆系统 · 第 3 块
> 一行字：**给 agent 五只手，让它能翻自己的记忆 —— 不翻，它就只能凭印象编。**

---

## 这模块干嘛

插件往系统提示里塞了人格、最近日记、目录路标。但那些只是**开头**。
agent 想到某件事、某个人的时候，得自己去翻。

这个模块注册五个工具：

| 工具 | 干什么 | 什么时候用 |
|---|---|---|
| `memory_find` | 按关键词找人和事，返回 id + 一句摘要 | 知道要找什么但不知道在哪本 |
| `memory_open` | 打开某一本读全文 | 拿到 id 之后 |
| `memory_diary` | 按日期看日记的「总结」段 | 想知道"那几天大概发生了什么" |
| `memory_recall` | 查某天的原始对话 | **只在写日记前拿稿子、或真要回查时** |
| `memory_index` | 看自己画的认知版图（INDEX.md） | 刚醒来、或想不起东西藏在哪 |

`memory_recall` 单独说明：它一晚上能吐出几百行原文，**拿它当日常会把上下文撑爆**。
所以工具描述里明确写了"只在两个场合用"。

## 怎么跑

```bash
cd <仓库根>/src/Search && node test/run.js
```

## 怎么验

- `TOOL_KEYS` 和实际注册的工具**必须一致**（测试钉着）
- 关掉某个工具后，它不该被注册
- 没有 `tools` 服务时要报一次，不能静默

## 三条硬边界

**① 只读，绝不写。**
五个工具全是读操作。写记忆是 agent 自己做（用 `write` / `edit`），
插件代劳会出问题 —— 它不知道 agent 当时的语气。

**② 只读自己的目录。**
路径全部从 `rootDir` 派生，不接受 agent 传任意路径。
跨人格的读取由 `lib/guard.mjs` 在 `tools/pre-execute` 拦。

**③ `memory_recall` 限流。**
默认最多 40 条，硬上限 200。它是这五个里最贵的。

## 不在了会怎样

工具没挂上，agent 还是能说话、能写字 ——
但它想不起细节时**只能凭印象说**，那就是编。

所以这块的 `parts` 状态是 `missing` 时，设置页体检会红。

## 几个想清楚了的地方

**为什么工具描述要写"什么时候用"，不只写"干什么"。**
模型看工具时，选不选它取决于场景描述，不取决于能力描述。
写"按关键词找人和事"它不一定知道该用；写"你知道要找什么但不知道在哪本"它就知道。

**为什么 `memory_index` 最后才加。**
它和 `memory_find` 有重叠（都能定位位置），但用途不同：
`find` 是按关键词搜，`index` 是"我现在一片空白，先看看地图"。
后者是**刚醒来时**用的，前者是**想起某件事时**用的。
