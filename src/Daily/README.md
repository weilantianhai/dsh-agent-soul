# Daily —— 晚上叫醒它，做一次记忆归档

> → 这份讲**怎么用**：模块干什么、怎么跑、怎么验、硬边界在哪。查函数签名去 [`API-REFERENCE.md`](API-REFERENCE.md)。

> DSH 记忆系统 · 第 4 块
> 一行字：**到点叫醒它，让它把今天沉淀下来 —— 日记、认识的人、经验、目录。**

---

## 这模块干嘛

DSH 的上下文会被压缩。压完之后，今天聊过什么、想明白什么，全没了。

所以每天到点（默认 23:30），挑出**有资格的会话**，各投一条叫醒消息：
「你今天在这个会话里待过，来复盘一下。」

叫醒词里让 agent 做**四件事**（不是只写日记）：

1. 写今天的日记 → `agents/<人格>/diary/<会话>/<日期>.md`
2. 更新认识的人 → `agents/<人格>/people/`
3. 更新经验库 → `agents/<人格>/经验.md`
4. 维护目录 → `agents/<人格>/INDEX.md` + `MEMORY.md`

这句话在 `prompts/daily/00-wake.md` 里，**你可以直接改**。

## 谁会被叫醒（四件事筛）

按顺序，任何一条不满足就跳过：

| # | 条件 | 为什么 |
|---|---|---|
| 1 | 不是子代理（`origin !== 'subagent'`） | 子代理的活是临时的，不写日记 |
| 2 | 不空（`blank !== true`） | 建过但没说话的会话没内容 |
| 3 | 今天动过（`updatedAt` 是本地今天） | 昨天的不算 |
| 4 | 有归属人格 | 没绑人格 = 临时会话，没地方写 |
| 5 | 有内容（今天日志 ≥ `minLines`，默认 6 行） | 只有一两句的，不值得单独写一篇 |
| 6 | 今天还没叫过 | 除非 `force` |

**正在跑的会话照样叫。** 用的是 `mode: 'queue'`，消息排队，等它这一轮结束自己会处理。
把"忙"当跳过理由，会导致"在对话里点按钮 → 自己永远收不到"。

## 怎么跑

```bash
cd <仓库根>/src/Daily && node test/run.js
```

手动触发（不等晚上）：设置页「出问题了」区块 → **立刻写日记**。
走的是同一个 `runOnce`，force 忽略"今天已经叫过"。

## 怎么验

- 今天该叫的会话都叫了，不该叫的都跳了
- 叫醒词里有四件事、有会话号、有绝对路径
- 一天只叫一次（再跑被挡）
- **手动触发和定时触发产出的叫醒词一字不差** —— 会话分不出哪个是手点的

## 三条硬边界

**① 只动自己的目录。**
路径全部从 `rootDir` + `agentId` 派生，不碰别人的。

**② 不改已经写好的日记。**
`ensureDiary` 只在文件不存在时建壳；已经有内容的一个字都不动。

**③ 一天只跑一次。**
记在 `system/daily.state.json`，按日期。**失败也算跑过**（不重试，免得反复打扰）。

## 不在了会怎样

晚上不叫。死了的会话今晚什么都不会写 —— 明天醒来它就不记得今天。

设置页的 `parts.Daily` 会显示 `missing`，体检会红。

## 几个想清楚了的地方

**为什么叫醒词里要放绝对路径。**
只说 `people/`，agent 不一定找得到 —— 不同会话的 `cwd` 不一样。
所以四个动作涉及的路径全部写成绝对路径。

**为什么叫醒词要说"四件事"。**
只说"写日记"，agent 就真的只写日记，认识的人、经验、INDEX 全不动。
日记只记"发生了什么"，那三样才记"我变成了什么"。

**为什么要先 `prompt` 再 `flush`。**
`prompt()` 返回 `{accepted:true}` **只代表消息进了内存里的 inbox**，
不等于落盘。必须 `sessions.flush(session)` 才算真的送到。
没落盘就不算叫过（记 `wake-unflushed`，下次还能重试）。

**为什么 `minLines` 默认 6。**
一两句对话写不出有内容的一篇，硬写就是流水账。
