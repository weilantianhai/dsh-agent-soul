# 五个记忆工具

> **是什么**：`memory_index` / `memory_find` / `memory_open` / `memory_diary` / `memory_recall` 的说明。
> **在哪**：`modules/Search/index.mjs`，通过 `ctx.tools.register()` 注册。
> **和说明书的关系**：说明书里只有一句干巴巴的摘要；**工具自己的 description 才是模型真正读到的完整说明**。
> **注意**：这两处说同一件事，改的时候要一起改，否则模型会读到两套说法。

---

## 五个工具怎么分工

```
刚醒来 / 不知道有什么  →  memory_index（看地图，很便宜）
知道要找什么          →  memory_find（关键词检索）
摘要不够 / 要引用原话  →  memory_open（读全文）
想知道这几天干了什么   →  memory_diary（日记的总结段）
要那天的原话          →  memory_recall（原文，很占上下文）
```

**顺序很重要**：先地图（便宜）→ 再检索（中等）→ 最后读全文（贵）。

---

## ① memory_index

看一眼自己写的记忆地图（`INDEX.md`）。

**什么时候用**
1. 刚醒来、脑子一片空白，想找回"我是谁、经历过什么"的领地感
2. 主人提起某件事，有模糊印象但不知道藏在哪 —— 先看地图
3. 今天有新感悟/认识了新人，想添砖加瓦时，看看版图决定放哪

**没有 INDEX.md 时**：不是只说"没有"，而是告诉它该建、该写哪几项，并列出当前目录里有什么。

---

## ② memory_find

按关键词找（认识的人、经验、日记、索引、人格）。

**什么时候用**：主人提到「上次」「之前」「那次」「那个问题」「我们讨论过」，或者你要说"我记得"的时候。

**返回**：命中位置的 id + 一句摘要。拿不准就 `memory_open` 读全文。

**别用它查原始对话** —— 那是 `memory_recall` 的事。

---

## ③ memory_open

打开一本记忆文件读全文。

**什么时候用**：`memory_find` 给的是一句摘要 —— 要靠它下判断、要引用原话、要看清前后文，就读全文。

**别拿摘要当事实回答。**

---

## ④ memory_diary

按日期读日记，默认最近 10 天，**只给每天「总结」那一段**（正文不给）。

**什么时候用**：「最近怎么样」「这几天在干嘛」，或者写日记前想回忆。

日记按 agent 归属 —— 同一个人的其他会话写的日记也能读。

---

## ⑤ memory_recall

查某天的原始对话。

**默认覆盖这个人名下所有会话** —— 同一个 agent 的几段日子会合并、按时间排、标出是哪段会话。

**只在两个场合用**：
1. 写日记前拿稿子
2. 真出问题要回查

**别的场合别用** —— 一晚上几百行原文，会把上下文撑爆。

---

## 一条设计原则

每个工具的 description 都要回答三个问题：

- **它是什么**（干什么的）
- **什么时候用它**（触发信号）
- **什么时候别用它，该用什么**（禁区 + 替代）

只写第一条，模型不会想起来去用。
