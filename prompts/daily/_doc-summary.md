# 上下文快满时写交接总结

> **什么时候触发**：上下文占用到阈值（默认 80%），**且它不忙**
> **存到**：`agents/<人格>/summary/<会话>/<日期>-<时分>.md`
> **模板**：词写在 `lib/summary.mjs` 的 `summaryPrompt()` 里（目前是代码）

---

## 为什么要这个

会话被压缩（compaction）之后，细节会丢。而「我这一段干了什么、做到哪、下一步接什么」——**只有 agent 自己知道**。

所以赶在压缩之前，让它先写一份。下次醒来先读这个，比读被压扁的历史强。

---

## 和日记的区别

| | 日记 | 交接总结 |
|---|---|---|
| 写什么 | 我过了一天 | 我干到哪了、下一步接什么 |
| 什么时候 | 每天晚上 | 上下文快满时 |
| 给谁看 | 明天的自己 | **接着干活的自己** |
| 风格 | 可以有温度 | **必须具体、可执行** |

提示词里专门写了「**这不是日记**」——不写这句，它一定写成心情散文，对下一次醒来毫无用处。

---

## 判定链路

```
读宿主注册的 contextPressure 投影
  → { pressureTokens, contextWindow }
算比例 → 超过阈值？
  是 → 排队（不立即发）
  等 agent/status 变 idle（宿主自己发的）
    → 这时候才发
```

**为什么排队**：到 80% 的时候它可能正在跑长任务。这时候插一句话进去会打断它，而且那句话会混进当下的工具链里。

**为什么用 `contextPressure` 而不是自己 tokenize**：宿主已经算好了，包括模型的实际窗口大小。自己估会飘。

---

## 几个边界

| 情况 | 行为 |
|---|---|
| 拿不到 `contextWindow` | 不动（不猜） |
| 没绑人格的会话 | 跳过（没地方放，也没有"我"） |
| 反复 idle | 只叫一次，不重复打扰 |
| 很忙 | 排队，等它不忙 |

---

## 阈值怎么调

设置页「默认」→「上下文到多少写交接总结」，可选 50%~90%。

存的是 `config.summary.threshold`（0~1 的小数）。

**不调代码。** 但注意：设置页之外改这个值，要保证在 0 和 1 之间，否则会退回 0.8 并报一条错。
